## 1. 這個系統做什麼

使用者戴上頭戴裝置（開發階段為桌面模擬器），在真實空間中：

1. 用控制器指向一面牆
2. 從四個風格選項中選一個
3. 等待 15 秒
4. 該位置出現一張對應風格的圖片

**研究對象只有第 3 步：等待期間，那塊空間呈現什麼。**

共三種呈現條件（C1／C2／C3），由網址參數決定。其餘所有行為在三條件下完全相同。

### 範圍

| | 申請前原型（本規格） | 執行期系統 |
|---|---|---|
| 平台 | XR Blocks 桌面模擬器 | Meta Quest 3S 瀏覽器 |
| 圖片來源 | 預先準備好的檔案 | 同左（正式實驗）；另加即時生成 API（僅用於 RQ1 可行性驗證） |
| 目的 | 證明三條件做得出來 | 正式實驗 |

**本規格只涵蓋左欄。** 不實作任何生成 API 呼叫。

## 2. 執行流程

### 狀態機

四個狀態，依序推進：

```
IDLE → TARGETED → WAITING → DONE
                              ↓ 按 R
                            IDLE
```

| 狀態 | 進入條件 | 畫面上有什麼 |
|---|---|---|
| `IDLE` | 程式啟動，或在 DONE 時按 R | 只有模擬器場景 |
| `TARGETED` | 使用者點到一面垂直牆 | 目標位置出現細框標記；風格選單出現 |
| `WAITING` | 使用者點了某個風格 | 選單消失；依條件而定（第 3 節） |
| `DONE` | 等待滿 15 秒 | 結果圖片出現在目標位置 |

按 `R` 從 `DONE` 回到 `IDLE`，試次編號加一。

### 步驟細節

**IDLE → TARGETED**

使用者以控制器（模擬器為滑鼠左鍵）指向平面並點擊。系統取得該點的世界座標與平面法向量。

判定條件，三者皆須成立：

- 平面 `orientation` 轉小寫後等於 `'vertical'`
- 交點與相機距離在 0.8m 至 4.0m 之間
- 交點距平面邊緣至少 `panelSize / 2`，確保整個面板落在平面上

任一條不成立就不做任何事，維持 `IDLE`，不顯示錯誤。

**TARGETED → WAITING**

風格選單出現後，使用者點其中一個方塊。記下風格代號，隱藏選單，立即進入 `WAITING`。

**WAITING → DONE**

計時 15 秒。等待期間的視覺呈現由條件決定（第 3 節）。`PoseLogger` 持續記錄。

**DONE**

移除等待期間的所有視覺元素，在目標位置建立貼有對應圖片的平面。

## 3. 三條件規格（研究核心）

### 面板的位置與朝向

三條件的佔位面與結果圖都是同一個幾何：

| 項目 | 值 |
|---|---|
| 形狀 | 正方形平面（`THREE.PlaneGeometry`） |
| 邊長 | `panelSize` = 0.8m |
| 位置 | 命中點 + 平面法向量 × 0.01m（避免 z-fighting） |
| 朝向 | 見下方 |

**朝向規則（重要）**

面板的 −Z 軸對齊牆面法向量（也就是面板正面朝向房間內），**上方向盡可能接近世界的正上方**。

這一條必須明確，否則面板會繞著法向量任意旋轉，圖片看起來是歪的或倒的。

實作上：以法向量與世界上方向量 `(0,1,0)` 建立一組正交基底，用它組出 quaternion。若法向量剛好接近垂直向上（本專案不會發生，因為只接受垂直面），才需要備用軸。

**面板不追隨使用者。** 一旦放置就固定在世界座標，使用者走動時面板不動。不要做 billboard。

### 共通設定

三條件的以下項目**完全相同**：

| 項目 | 值 |
|---|---|
| 面板尺寸、位置、朝向 | 同上 |
| 等待時長 | 15.0 秒 |
| 選取流程 | 相同 |
| 結果圖片 | 相同 |

### C1　基線

等待期間空間中**無任何變化**。15 秒後圖片直接出現。

實作：`WAITING` 期間不建立任何 mesh。

### C2　佔位

進入 `WAITING` 時立即建立佔位面，維持不變直到計時結束後替換為結果圖。

佔位面由**兩層 quad** 組成：

| 層 | 邊長 | 顏色 | 不透明度 |
|---|---|---|---|
| 邊框層（後） | 0.84m | `0xffffff` | 0.7 |
| 填充層（前） | 0.80m | `0xffffff` | **0.4** |

兩層間距 0.002m，邊框層在後（離牆較近）。

**為什麼不用 LineBasicMaterial 畫邊框**：WebGL 的線寬在絕大多數平台上被忽略，`linewidth: 2` 只會畫出 1px 的線，在頭戴裝置上幾乎看不見。用一個略大的 quad 當底最可靠。

### C3　漸進顯現

結構同 C2，但**填充層**的不透明度隨時間增加。**邊框層維持 0.7 不變。**

| 參數 | 值 |
|---|---|
| 填充層起始不透明度 | 0.1 |
| 填充層結束不透明度 | 0.5 |
| 曲線 | 三次 ease-out |

```js
const t = Math.min(elapsed / duration, 1);       // 0 → 1
const eased = 1 - Math.pow(1 - t, 3);            // 三次 ease-out
const opacity = 0.1 + (0.5 - 0.1) * eased;
```

### 為什麼 C2 的填充層是 0.4

C3 填充層的不透明度在 15 秒內的**時間平均值**是 0.4，不是區間中點 0.3。

三次 ease-out 的積分：

```
∫₀¹ [1 - (1-t)³] dt = 1 - 1/4 = 0.75
平均不透明度 = 0.1 + (0.5 - 0.1) × 0.75 = 0.4
```

C2 設為 0.4 使兩條件在整段等待期間的**累積視覺強度相同**，差異就只剩「變不變」。這是為了讓操弄乾淨，不是隨意取值。

### 三條不可違反的規則

1. **C2 與 C3 的佔位面都是中性白色，不得顯示結果圖片的任何內容。** 若佔位面預覽了最終外觀，C2 與 C3 就同時差在「內容資訊」與「動態」兩件事，條件間比較會混淆。
2. **C3 不得顯示百分比、剩餘秒數或任何數字。** 生成模型不回報真實進度，顯示精確進度構成不實資訊（見計畫書風險三）。
3. **C3 的曲線不得為線性。** 線性變化可被外推出完成時點，違反上一條的精神。

## 4. 模組

五個模組，各自獨立檔案，全部繼承 `xb.Script`。

### `PlacementController`

**職責**：IDLE → TARGETED。

| | |
|---|---|
| 輸入 | 選取事件 |
| 輸出 | `{position: Vector3, quaternion: Quaternion}` 或 `null` |

實作要點：
- 三項判定條件見第 2 節
- 朝向的計算見第 3 節
- 命中測試的 API 見 CLAUDE.md；**該 API 尚未驗證，這是第一個要解決的問題**

### `StylePicker`

**職責**：TARGETED 期間顯示選單。

| | |
|---|---|
| 輸入 | 目標位置與朝向 |
| 輸出 | 風格代號（`'wood'` / `'brick'` / `'fabric'` / `'concrete'`） |

實作要點：
- 四個方塊，各 0.15m 立方，間距 0.05m，沿面板的水平軸排列
- 每個方塊用對應風格圖片當材質
- 位置：目標位置沿法向量向外 0.5m，與目標中心同高
- 選定後立即隱藏

### `WaitFeedback`（研究核心）

**職責**：WAITING 全程。三條件的差異**全部封裝在這個模組裡**，其他模組不需要知道現在是哪個條件。

| | |
|---|---|
| 輸入 | `{position, quaternion, condition, duration}` |
| 輸出 | 計時結束時的回呼 |

實作要點：
- `condition` 為 `'C1'` / `'C2'` / `'C3'`
- 計時：開始時記下 `performance.now()`，在 `update()` 裡比對經過時間
- **不使用 `setTimeout`**，因為 C3 需要逐幀更新不透明度，用同一套計時比較不會漂移
- 結束時清除自己建立的所有 mesh 並釋放材質

### `ContentApplier`

**職責**：DONE。

| | |
|---|---|
| 輸入 | `{position, quaternion, task, style}` |
| 輸出 | 無 |

實作要點：
- 檔名為 `${task}_${style}.png`（第 6 節）
- `THREE.TextureLoader` 載入，記得設 `colorSpace = THREE.SRGBColorSpace`
- 圖片尚未備妥時用純色代替，四風格各一色

### `PoseLogger`

**職責**：全程記錄。與其他四個模組完全獨立，只讀相機。

見第 5 節。

### 依賴關係

```
PlacementController ─┐
                     ├→ WaitFeedback → ContentApplier
StylePicker ─────────┘

PoseLogger（獨立）
```

## 5. 資料記錄

### 記錄什麼

`WAITING` 與 `DONE` 狀態期間，每一幀記錄一筆。`IDLE` 與 `TARGETED` 不記錄。

| 欄位 | 型別 | 內容 |
|---|---|---|
| `t` | number | `performance.now()`，毫秒 |
| `px` `py` `pz` | number | 相機位置 |
| `qx` `qy` `qz` `qw` | number | 相機朝向四元數 |
| `condition` | string | `C1` / `C2` / `C3` |
| `task` | string | `w1` / `w2` / `w3` |
| `style` | string | 選定的風格 |
| `trial` | number | 試次編號 |
| `phase` | string | `waiting` / `done` |

數值保留小數點後 4 位。

**試次編號**：程式啟動時為 1，每次按 `R` 重置加一。不跨頁面保存。

### 匯出

按 `E` 鍵匯出累積的所有資料為 CSV 下載。

檔名：`P{受試者編號}_{YYYYMMDD_HHmmss}.csv`

### 不做的事

- 不寫入 `localStorage`
- 不上傳伺服器
- 不做即時分析

## 6. 素材

| 項目 | 值 |
|---|---|
| 尺寸 | 1024 × 1024 |
| 格式 | PNG |
| 位置 | `assets/styles/` |
| 命名 | `{task}_{style}.png` |

共 12 個檔案：

```
assets/styles/
├── w1_wood.png   w1_brick.png   w1_fabric.png   w1_concrete.png
├── w2_wood.png   w2_brick.png   w2_fabric.png   w2_concrete.png
└── w3_wood.png   w3_brick.png   w3_fabric.png   w3_concrete.png
```

**三個任務各有自己的一套圖。** 若共用 4 張，受試者在第二、三輪會看到完全相同的圖片，新鮮感消失且會察覺系統在重複。

素材尚未備妥時，用純色方塊代替，不影響任何邏輯。

## 7. 參數集中管理

以下數值**必須**放在 `src/config.js`，不得散落在各模組。前測階段會反覆調整。

```js
export const CONFIG = {
  // 面板
  panelSize: 0.80,             // 填充層邊長，公尺
  borderSize: 0.84,            // 邊框層邊長
  surfaceOffset: 0.01,         // 離牆距離
  layerGap: 0.002,             // 邊框層與填充層間距

  // 選取判定
  minDistance: 0.8,            // 最近可選取距離
  maxDistance: 4.0,            // 最遠可選取距離

  // 時間
  waitDuration: 15.0,          // 等待秒數

  // 外觀
  placeholderColor: 0xffffff,
  borderOpacity: 0.7,          // 邊框層，三條件皆固定
  c2Opacity: 0.4,              // C2 填充層，固定
  c3OpacityStart: 0.1,         // C3 填充層起點
  c3OpacityEnd: 0.5,           // C3 填充層終點
  c3Easing: (t) => 1 - Math.pow(1 - t, 3),

  // 風格選單
  styles: ['wood', 'brick', 'fabric', 'concrete'],
  pickerCubeSize: 0.15,
  pickerSpacing: 0.05,
  pickerDistance: 0.5,

  // 資料
  decimalPlaces: 4,
};
```

## 8. 網址參數

| 參數 | 值 | 預設 | 用途 |
|---|---|---|---|
| `c` | `C1` / `C2` / `C3` | `C1` | 條件 |
| `p` | 字串 | `00` | 受試者編號 |
| `task` | `w1` / `w2` / `w3` | `w1` | 任務，決定用哪一套圖片 |

範例：`http://127.0.0.1:8081/?c=C2&p=03&task=w2`

**`task` 只決定圖片集，不決定使用者要點哪面牆。** 實驗時由施測者口頭指定目標牆面，並將網址設為對應的 task。

實驗中由施測者手動改網址切換，**不做條件切換的 UI**。

## 9. 明確不做

- 不呼叫任何生成 API
- 不做自由文字輸入
- 不做物件移除或 inpainting
- 不做深度遮擋（執行期的進階項目）
- 不做水平面放置（三個任務都是牆面）
- 不做 billboard（面板不追隨使用者）
- 不做多人、帳號、伺服器
- 不做陰影、物理、粒子
- 不做條件切換 UI
- 不做即時資料分析
- 不追求圖片的視覺品質
- 不修改 `../xrblocks/` 的任何檔案

每刪掉一項，可用的系統就早一天出現。

## 10. 驗收

1. 開 `?c=C1`，點牆、選風格、等 15 秒，圖片出現且方向正確（不歪不倒）
2. 開 `?c=C2`，同上，但等待期間看得到半透明白色方塊與較明顯的邊框
3. 開 `?c=C3`，同上，但填充層由淡變明顯，邊框不變
4. 三條件的面板位置、尺寸、朝向、等待時間完全一致
5. 走到面板側面，面板不會轉向跟著你
6. 按 `E` 下載到能用試算表開啟的 CSV，欄位齊全
7. 按 `R` 可重置並開始下一試次，試次編號遞增
8. 換 `?task=w2`、`?task=w3` 都能運作
